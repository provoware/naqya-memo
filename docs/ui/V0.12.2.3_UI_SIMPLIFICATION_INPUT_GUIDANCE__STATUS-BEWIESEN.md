# V0.12.2.3 – UI Simplification & Input Guidance

## Ziele
- Eingabefelder farblich von den Markenfarben lösen.
- In allen benutzbaren Eingabefeld-Kategorien optionale Beispiele oder Vorgaben anzeigen.
- Versionsinformation nur einmal sichtbar darstellen.
- Bedienkomplexität und doppelte Informationen reduzieren.
- Linke Schnellnavigation, Darstellungskarte und Zoomverhalten gegen Überlauf härten.

## Umsetzung

### Eingaben
Neutrale Silber-/Graphit-Palette:
- Rahmen `#b7c1cc`
- Fokus `#f4f7fb`
- dunkle neutrale Feldflächen

Türkis, Lila und Gelb bleiben Marken-/Statusfarben und werden nicht als Eingabefeldrahmen verwendet.

### Optionale Vorgaben
Text, Titel, Tags, Beschreibungen, Datum/Zeit, Reminder, Priorität, Farbe, Datei, Pfad, Hilfemodus, Kalenderlegende, Schnellmemo und Dokumenteditor besitzen Beispiel-/Hilfetexte. Sie sind Hinweise und werden niemals als Nutzerdaten erzwungen.

### Version
Einzige sichtbare Stelle: rechte Karte `TOOL-INFO → Version`.
Branding, Statuszeile, Dashboard, Footer und Entwicklerkopf wiederholen die Versionsnummer nicht.

### Komplexitätsreduktion
- Status oben: 4 → 3 Kacheln
- Dashboard: 6 → 4 Hauptkarten
- Einstellungen: nur Hilfemodus; Darstellungssteuerung bleibt oben
- redundante Schnellleisten-/Workspace-Hinweise entfernt

### Layout
- Navigation ohne horizontale Mini-Scrollbar
- abgestufte Nav-Breite für Schriftvergrößerung
- 80–200 % Bereichszoom ordnet Formulare/Listen neu an
- Hauptcontainer nutzen `min-width:0`, Maximalbreiten und horizontale Überlaufbremsen
- bei engen Viewports fällt Zusatzinformation vor dem Arbeitsbereich weg

## Browser-Evidence
Der aktuelle Build-Runner blockiert Chromium über DBus/Headless-Timeout. Deshalb wird kein Visual-PASS behauptet.
`RUN_VISUAL_ACCEPTANCE_LINUX.sh` prüft auf dem realen Linux-Zielrechner alle Kernansichten und schreibt Screenshots/Evidence.
